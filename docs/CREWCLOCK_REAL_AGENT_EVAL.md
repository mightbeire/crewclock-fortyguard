## Runtime contract

The configured production provider is Groq `openai/gpt-oss-120b` through the OpenAI-compatible Chat Completions endpoint. CrewClock passes only local function definitions and executes returned function calls itself. Groq browser search, code execution and remote orchestration are not used. The adapter uses a bounded request timeout, one retry ceiling by default, compact state/tool observations, and usage counters.

Required later configuration names are `LLM_PROVIDER`, `GROQ_API_KEY`, and `GROQ_MODEL`. The expected values are `groq` and `openai/gpt-oss-120b` for the non-secret fields.

### Rate-aware real execution

All CrewClock Groq calls share one `GroqRateGovernor`. It parses runtime `x-ratelimit-*` and `retry-after` durations, tracks remaining token/request capacity and actual usage, proactively waits with a configurable safety reserve, retries the same logical request up to three times on 429, and uses bounded exponential backoff for transient 5xx/timeout failures. Trials run strictly sequentially. The governor is infrastructure reliability, not a CrewClock product feature.

Every trial is checkpointed under `evidence/crewclock-real-agent-eval/checkpoint.json` before and after execution. A restart hydrates the saved rolling capacity snapshot and resumes at the first in-progress/incomplete trial; completed trials are not repeated unless `--rerun` is supplied. Checkpoints contain only high-level tool traces, sanitized rate headers, classifications and token counts—never provider messages, reasoning, or secrets.

Failure classifications are mutually exclusive: `AGENT_BEHAVIOR_FAILURE`, `DETERMINISTIC_TOOL_FAILURE`, `EVALUATOR_FAILURE`, `PROVIDER_RATE_LIMIT`, `PROVIDER_TRANSIENT_FAILURE`, and `PROVIDER_FATAL_FAILURE`.

Official references: [Groq OpenAI compatibility](https://console.groq.com/docs/openai), [local tool calling](https://console.groq.com/docs/tool-use/local-tool-calling), and [GPT-OSS 120B](https://console.groq.com/docs/model/openai/gpt-oss-120b).

## Safety proofs

- `COMPLETED_BUT_EMPTY = INVALID_EVIDENCE`: an empty heatmap fixture is rejected by the raw-response schema guard and never becomes thermal evidence.
- Cached-live thermal evidence must be explicitly supplied as a fixture and returns `source = CACHED_LIVE_FORTYGUARD`; the runtime path cannot silently call FortyGuard.
- Unknown tools, missing/invalid arguments, extra arguments where disallowed, repeated calls, oversized input, model-call caps and tool-call caps fail closed.
- A full CrewClock registry cannot accept a recommendation before a successful deterministic verification observation.
- Approval is represented as a pending human gate; the LLM cannot approve itself.
- Only high-level operational events are stored in the trace. Raw provider reasoning fields are ignored.
