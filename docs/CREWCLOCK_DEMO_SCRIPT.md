# CrewClock Final Demo Script

## Demo target

- Target duration: **2:10–2:25**.
- Hard limit: **under 3 minutes**.
- Use the verified Palm Springs browser path.
- Use the existing cached-live FortyGuard evidence. State this clearly.
- Do not depend on a fresh provider call during the recorded demo.
- Keep the superintendent approval step visible.

## 0:00–0:15 — The problem

Show the Palm Springs shift before the recommendation.

> “A construction superintendent cannot move outdoor work just because a forecast looks hot. Crews, fixed commitments, qualifications, dependencies, and deadlines still have to work. CrewClock turns hyperlocal thermal evidence into a verified pre-shift decision.”

## 0:15–0:35 — The agent investigates

Start the review once. Show the activity state briefly.

> “The AI agent reviews the submitted shift and decides which workfaces and time windows need investigation. Those validated choices control the FortyGuard evidence requests. The agent does not choose schedule times or approve its own recommendation.”

## 0:35–0:55 — The recommendation

Let **I found a better sequence** appear.

Show the schedule and the moved task blocks.

> “CrewClock then tests feasible alternatives with deterministic schedule checks. Fixed work stays anchored. Here, three flexible tasks move while all six constraint families still pass.”

## 0:55–1:15 — The measured change

Point to **13h → 4h**.

> “Scheduled High-Heat Crew-Hours falls from 13 to 4. That is nine fewer scheduled crew-hours inside the modeled high-heat window. SHHCH is a schedule-placement metric. It is not a medical exposure score or a safety certification.”

## 1:15–1:35 — Show the proof

Open **Why this plan?**

Show the FortyGuard evidence card and the proof chain.

> “This run reuses previously acquired live FortyGuard evidence after an exact site-and-time identity match. CrewClock connects that evidence to the workface, the task schedule, the measured overlap, and the verified alternative.”

## 1:35–1:55 — Human authority

Close the proof panel. Show **Approve plan** and **Keep current shift**.

> “CrewClock stops here. The superintendent keeps final authority.”

Click **Approve plan**.

Show **APPROVED · VERIFIED** and **Shift updated**.

> “After approval, CrewClock verifies the exact recommendation again before the shift becomes final.”

## 1:55–2:15 — Close

Show the final schedule and the approved state.

> “CrewClock is not another weather dashboard. The agent decides what evidence to investigate. FortyGuard supplies the modeled environmental evidence. Deterministic code verifies the schedule. The superintendent decides whether to use it.”

## Optional 10-second boundary proof

Use this only if the recording is still below the time limit.

Show an evidence-unavailable state.

> “If CrewClock cannot establish usable evidence, it keeps the current shift. It does not invent a zero value or fabricate a recommendation.”

## Judge questions

### Why use AI?

> “The agent decides whether investigation is needed and which workfaces and time windows need evidence. Those choices control the evidence path. Deterministic code owns schedule arithmetic and verification.”

### Why is this not a weather dashboard?

> “CrewClock connects workface-level evidence to the actual construction shift. It then tests schedule alternatives against hard operational constraints and presents one verified decision to the superintendent.”

### What is SHHCH?

> “Scheduled High-Heat Crew-Hours measures scheduled crew-hours that overlap the configured modeled high-heat window. It is a planning metric, not a physiological exposure measure.”

### Is CrewClock a safety system?

> “No. CrewClock supports pre-shift planning. Employer policy, onsite measurement, trained supervision, and professional judgment remain authoritative.”

### What happens when evidence is missing?

> “CrewClock preserves the current schedule and reports that evidence is unavailable. It does not fabricate a recommendation.”
