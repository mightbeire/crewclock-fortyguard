# Realistic public input-data research

The live FortyGuard data is real, but operational inputs still need realistic structures. The following sources are free/public or publicly documented; no paid data, credentialed feed, or private customer data was used.

| Workflow | Source | Useful fields/schema | Status and limitation |
|---|---|---|---|
| Surface-conditioned road repair | [MyLA311 2024](https://data.lacity.org/City-Infrastructure-Service-Requests/MyLA311-Service-Request-Data-2024/b7dx-7gc3), [Portland PBOT maintenance](https://www.portlandmaps.com/arcgis/rest/services/Public/PBOT_Maintenance/MapServer/layers) | LA: request ID, created/updated/closed dates, request type, owner, status, assignment, latitude/longitude. Portland pothole layer: item ID/status/date/category/neighborhood/point; related maintenance layers include street, from/to, completion date, geometry. | Strongest public input path. LA Socrata row access returned HTTP 403 from this environment, so no raw rows were copied; the official schema is documented and the spike uses a clearly labeled schema-faithful fixture. Portland’s REST schema is public and queryable. |
| RailHeat Patrol Sequencer | [FRA ATIP](https://railroads.fra.dot.gov/railroad-safety/partnerships-programs/automated-track-inspection-program-atip), [FRA safety data](https://railroads.fra.dot.gov/safety-data), [Grade Crossing Inventory metadata](https://safetydata.fra.dot.gov/MasterWebService/SecureApi/Support/Datasets?ModelType=Crossings) | rail/crossing identifier, railroad, state/county/city, line segment, location, inspection/defect/incident context; live operator systems would add milepost, track class, crew windows, train conflicts, and criticality. | Good public asset/inventory context and authoritative heat-inspection rationale, but detailed railroad work orders and track geometry can require operator access. |
| Utility vegetation release | [California Energy Safety GIS standard](https://energysafety.ca.gov/wp-content/uploads/energy-safety-gis-data-reporting-standard_version2.1_09072021_final.pdf), [Hydro-Québec vegetation schedule](https://donnees.hydroquebec.com/explore/dataset/calendrier-travaux-degagement-distribution-json/) | utility ID, circuit/line, tree ID, project/work package, location, planned/completed dates, vegetation treatment type, contractor. | Public schema/proxy exists; Hydro-Québec is outside the U.S.-only event scope and is used only as a schema reference, not demo data. |
| Airport apron operations | [FAA Aviation Facilities](https://catalog.data.gov/dataset/aviation-facilities-9c677), [FAA airport data portal](https://www.faa.gov/data) | airport identifier, facility type, location, operations/enplanements, usage category; airport diagram releases add taxiways, aprons, buildings, hotspots. | Good geography and public facility context; ramp task rosters/labor/turnaround data are not public. |
| Telecom maintenance | [ITU-T M.3370](https://www.itu.int/epublications/publication/itu-t-m-3370-2025-03-telecommunication-preventive-maintenance-task-overview/en) | network element, preventive task, priority, work order, executor/resource, status, verification result. | Strong documented schema and agent loop; site inventory and SLA data remain private. |
| Solar O&M | [PV cleaning scheduling research](https://doi.org/10.1016/j.renene.2025.122971), [NREL data center/PV resources](https://www.nrel.gov/gis/) | site/array, row/sector, generation, soiling estimate, cleaning cost, water/crew capacity, weather window, completion/production delta. | Credible operational model; actual plant telemetry is usually private. Satellite labels must not be treated as panel identification. |
| Commercial property/parks work orders | [NYC AMPS work orders](https://catalog.data.gov/dataset/asset-management-parks-system-amps-work-orders) | work-order ID (`EVT_CODE`), asset reference (`EVT_OBJECT`/`OBJ_CODE`), description, assigned title, request/completion dates, status. | Public, explicit work-order-to-asset join; geography differs from tested FortyGuard sites, so use as schema/prototype input only. |
| Transit stop/route operations | [FTA GTFS guidance](https://www.transit.dot.gov/ntd/2023-ntd-data-collection-and-reporting), [San Diego transit stops](https://data.sandiego.gov/datasets/gis-transit-stops/) | stop_id, stop_name, lat/lon, route/trip/stop times, shelter/amenity fields where provided. | Excellent public spatial/schedule structure; intervention and crew constraints still need a city partner. |
| Warehouse/dock shifts | [OSHA warehousing hazards](https://www.osha.gov/warehousing/hazards-solutions), [MangoApps heat playbook](https://www.mangoapps.com/templates/heat-illness-prevention-playbook) | zone, dock/door, shift, task intensity, staffing, break/cooling location, acclimatization status, throughput target. | Realistic documented schema; no public facility roster was adopted because it would be too synthetic without a site. |
| Fleet/waste routes | [GTFS/transport schedule concepts](https://gtfs.org/documentation/schedule/reference/), municipal route/work-order portals | route, stop, vehicle, service window, tonnage/task, depot, break/recovery location. | Public schedule formats exist, but heat-sensitive municipal fleet work data is fragmented and city-specific. |
| Data-center facilities | [NREL data-center best practices](https://www.nrel.gov/docs/fy24osti/89843.pdf), [DOE data-center cooling](https://www.energy.gov/cmei/femp/cooling-water-efficiency-opportunities-federal-data-centers) | site, cooling plant, maintenance window, load, outside air, humidity, solar exposure, energy/water limit, approval state. | Strong domain schema; live telemetry and critical thresholds are private and high-risk.

## Input-side conclusion

The best realistic demo inputs are the public road-maintenance/work-order structures and the FRA/rail inventory structures. They support a believable “ingest → rank → propose → verify” agent without pretending to have private enterprise integrations. Thermal Sequence Planner remains easier to prototype with a generic job schema, but its adoption story is weaker until a public or partner-like route dataset is attached.
